In deze bijlage worden begrippen en afkortingen toegelicht die in het globaal ontwerp van Gemeenschappelijke Bronontsluiting worden gebruikt. De uitleg beschrijft wat het begrip binnen de context van GBO betekent. Het betreft daarmee niet altijd een volledige juridische of technische definitie.

| Begrip | Uitleg |
| ------ | ------ |
| **Afnemer** { #begrip-afnemer } | Organisatie of persoon die gegevens opvraagt bij een [bronhouder](#begrip-bronhouder). Dit kan bijvoorbeeld een overheidsorganisatie, een private dienstverlener, een burger met een [EUDI-Wallet](#begrip-eudi-wallet), een [QTSP](#begrip-qtsp) of een voorziening binnen een Europese gegevensuitwisseling zijn. |
| **API** { #begrip-api } | *Application Programming Interface*. Een gestandaardiseerd koppelvlak waarmee systemen geautomatiseerd gegevens of functionaliteit kunnen opvragen. |
| **ARF** { #begrip-arf } | *Architecture and Reference Framework*. Het Europese architectuur- en referentiekader met afspraken, protocollen en formaten voor de [EUDI-Wallet](#begrip-eudi-wallet). |
| **AS4** { #begrip-as4 } | Berichtenstandaard die binnen [eDelivery](#begrip-edelivery) en [OOTS](#begrip-oots) wordt gebruikt voor veilige grensoverschrijdende uitwisseling van berichten. De [Basisinrichting OOTS](#begrip-basisinrichting-oots) handelt het AS4-verkeer voor Nederlandse [bronhouders](#begrip-bronhouder) af. |
| **ASI** { #begrip-asi } | *Authentic Source Interface*. Gestandaardiseerd koppelvlak waarmee een [QTSP](#begrip-qtsp) gegevens bij een authentieke bron kan verifiëren of ophalen voor de uitgifte van een [QEAA](#begrip-qeaa). |
| **ASI-provider** { #begrip-asi-provider } | Technische rol of voorziening die een [Authentic Source Interface](#begrip-asi) aanbiedt. In het globaal ontwerp wordt deze soms afgekort als **ASI-P**. |
| **Attestatie** { #begrip-attestatie } | Digitaal bewijs waarin één of meer [attributen](#begrip-attribuut) over een persoon of organisatie zijn opgenomen. Een attestatie kan in een [EUDI-Wallet](#begrip-eudi-wallet) worden opgeslagen en aan een dienstverlener worden getoond. |
| **Attestatieschema** { #begrip-attestatieschema } | Formele beschrijving van de [attributen](#begrip-attribuut), structuur, betekenis en technische representatie van een [attestatie](#begrip-attestatie). |
| **Attribuut** { #begrip-attribuut } | Afzonderlijk gegeven over een persoon, organisatie of object, zoals een geboortedatum, bevoegdheid, diploma of vestigingsadres. |
| **Audit trail** { #begrip-audit-trail } | Samenhangende en chronologische registratie waarmee achteraf kan worden vastgesteld wie welke gegevens heeft opgevraagd, op welke [grondslag](#begrip-grondslag) dit gebeurde en welke controles zijn uitgevoerd. |
| **Authenticatie** { #begrip-authenticatie } | Het vaststellen dat een persoon, organisatie of systeem daadwerkelijk de identiteit heeft die het beweert te hebben. |
| **AuthZEN** { #begrip-authzen } | Gestandaardiseerd koppelvlak van de OpenID Foundation voor de communicatie tussen een [PEP](#begrip-pep) en een [PDP](#begrip-pdp). AuthZEN maakt het mogelijk om de technische onderdelen van de autorisatieketen onafhankelijk van elkaar te implementeren. |
| **Autorisatie** { #begrip-autorisatie } | Het bepalen of een geïdentificeerde en geauthenticeerde partij een bepaalde handeling mag uitvoeren of bepaalde gegevens mag opvragen. |
| **Basisinrichting OOTS** { #begrip-basisinrichting-oots } | Nederlandse voorziening voor aansluiting op het Europese [Once-Only Technical System](#begrip-oots). De voorziening handelt onder meer Europese berichten, herauthenticatie, inzage door de burger en verzending van bewijsgegevens af. |
| **Beleidsregel** { #begrip-beleidsregel } | Machineleesbare regel die bepaalt onder welke voorwaarden een gegevensverzoek is toegestaan. Een beleidsregel kan bijvoorbeeld betrekking hebben op de [afnemer](#begrip-afnemer), de [grondslag](#begrip-grondslag), het doel, de [gegevensset](#begrip-gegevensset) en de betrokken persoon. Ook aangeduid als *[policy](#begrip-policy)*. |
| **Beleidsgedreven autorisatie** { #begrip-beleidsgedreven-autorisatie } | Vorm van [autorisatie](#begrip-autorisatie) waarbij toegangsbeslissingen worden genomen op basis van centraal of decentraal beheerde [beleidsregels](#begrip-beleidsregel). Zie ook [**PBAC**](#begrip-pbac). |
| **Begrippenkader** { #begrip-begrippenkader } | Gestructureerde verzameling begrippen met definities en onderlinge relaties. Het begrippenkader vormt de gemeenschappelijke basis voor de betekenis van gegevens binnen [GBO](#begrip-gbo). |
| **Bronhouder** { #begrip-bronhouder } | Organisatie die verantwoordelijk is voor een gegevensbron en voor het beschikbaar stellen van gegevens uit die bron. De bronhouder blijft verantwoordelijk voor de gegevens, ook wanneer [GBO](#begrip-gbo)-voorzieningen worden gebruikt voor de ontsluiting. |
| **Bronontsluiting-API** { #begrip-bronontsluiting-api } | Generieke interface waarmee een [bronhouder](#begrip-bronhouder) gegevens beschikbaar stelt voor verschillende [GBO](#begrip-gbo)-interactiepatronen. Deze wordt functioneel ook aangeduid als de [**generieke bronontsluiting**](#begrip-generieke-bronontsluiting). |
| **BSN** { #begrip-bsn } | Burgerservicenummer. Identificerend nummer voor personen die in de Nederlandse Basisregistratie Personen zijn opgenomen. Het BSN mag alleen worden verwerkt door partijen die daarvoor een wettelijke [grondslag](#begrip-grondslag) hebben. |
| **BSNk PP** { #begrip-bsnk-pp } | [BSN](#begrip-bsn)-koppelregister polymorfe pseudoniemen. Voorziening waarmee identiteiten en pseudoniemen zodanig kunnen worden verwerkt dat een [afnemer](#begrip-afnemer) alleen een voor die afnemer bestemde identiteit of een [partijspecifiek pseudoniem](#begrip-partijspecifiek-pseudoniem) ontvangt. |
| **Canoniek gegevensmodel** { #begrip-canoniek-gegevensmodel } | Gestandaardiseerde beschrijving van de gegevens die een [bronhouder](#begrip-bronhouder) beschikbaar stelt. Het model vormt een stabiel tussenformaat waarop [mappings](#begrip-mapping) naar toepassingsspecifieke formaten kunnen worden gebaseerd. |
| **Consent-id** { #begrip-consent-id } | Unieke identificatie van een geregistreerde [toestemming](#begrip-toestemming). Een private dienstverlener kan deze identificatie meegeven bij een gegevensverzoek, zodat de [bronhouder](#begrip-bronhouder) de toestemming kan laten controleren. |
| **Credential** { #begrip-credential } | Digitaal bewijs met uitspraken over een persoon, organisatie of object. Binnen het [EUDI-Wallet](#begrip-eudi-wallet)-patroon gaat het doorgaans om een verifieerbare credential. Zie ook [**VC**](#begrip-vc). |
| **Data Service Directory** { #begrip-data-service-directory } | Europese [OOTS](#begrip-oots)-catalogus waarin kan worden opgezocht welke gegevensdiensten en bewijsleveranciers een bepaald type bewijs kunnen leveren. Afgekort als **[DSD](#begrip-dsd)**. |
| **Dataminimalisatie** { #begrip-dataminimalisatie } | Principe dat niet meer gegevens worden opgevraagd of verstrekt dan noodzakelijk is voor het doel van een dienst. [GBO](#begrip-gbo) ondersteunt dit onder meer door selectieve gegevensuitvraag. |
| **DCAT-AP NL** { #begrip-dcat-ap-nl } | Nederlands toepassingsprofiel van de Europese Data Catalog Vocabulary. Binnen [GBO](#begrip-gbo) wordt DCAT-AP NL gebruikt voor de gestandaardiseerde beschrijving en vindbaarheid van datasets en gegevensdiensten. |
| **Dienstencatalogus** { #begrip-dienstencatalogus } | Centrale catalogus van vooraf toegestane gegevensvragen per dienst of toepassing. De catalogus beschrijft welke [afnemer](#begrip-afnemer) voor welk doel welke gegevens mag opvragen. |
| **Doelbinding** { #begrip-doelbinding } | Eis dat gegevens uitsluitend worden verwerkt voor een vooraf bepaald, uitdrukkelijk omschreven en gerechtvaardigd doel. |
| **DQV** { #begrip-dqv } | *Data Quality Vocabulary*. W3C-vocabulaire voor het beschrijven van de kwaliteit van datasets en kwaliteitsmetingen. |
| **DSD** { #begrip-dsd } | *[Data Service Directory](#begrip-data-service-directory)*. Europese [OOTS](#begrip-oots)-catalogus waarin kan worden opgezocht welke gegevensdiensten en bewijsleveranciers een bepaald type bewijs kunnen leveren. |
| **DvTP** { #begrip-dvtp } | Naam voor het [GBO](#begrip-gbo)-interactiepatroon waarin een burger overheidsgegevens laat verstrekken aan een private dienstverlener. Hiervoor zijn onder meer [toestemming](#begrip-toestemming), [doelbinding](#begrip-doelbinding) en [pseudonimisering](#begrip-pseudonimisering) nodig. |
| **EAA** { #begrip-eaa } | *Electronic Attestation of Attributes*. Elektronische [attestatie](#begrip-attestatie) waarin [attributen](#begrip-attribuut) over een persoon of organisatie zijn opgenomen. Een EAA kan bijvoorbeeld als [PubEAA](#begrip-pubeaa) of [QEAA](#begrip-qeaa) worden uitgegeven. |
| **eBMS** { #begrip-ebms } | *ebXML Messaging Services*. Berichtenstandaard waarop [AS4](#begrip-as4) is gebaseerd en die wordt gebruikt voor de betrouwbare uitwisseling van elektronische berichten. |
| **eDelivery** { #begrip-edelivery } | Europese bouwsteen voor veilige en betrouwbare elektronische gegevensuitwisseling. [OOTS](#begrip-oots) gebruikt een [AS4](#begrip-as4)-profiel van eDelivery voor het berichtenverkeer tussen lidstaten. |
| **eID** { #begrip-eid } | Elektronisch identificatiemiddel waarmee een persoon digitaal zijn identiteit kan aantonen. |
| **eIDAS** { #begrip-eidas } | Europees juridisch kader voor elektronische identificatie en vertrouwensdiensten. De herziene verordening vormt onder meer de basis voor de [EUDI-Wallet](#begrip-eudi-wallet) en elektronische [attestaties](#begrip-attestatie) van [attributen](#begrip-attribuut). |
| **eIDAS2** { #begrip-eidas2 } | Informele aanduiding voor de herziene Europese [eIDAS](#begrip-eidas)-verordening, die onder meer de juridische basis vormt voor de [EUDI-Wallet](#begrip-eudi-wallet). |
| **EER** { #begrip-eer } | Europese Economische Ruimte. Samenwerkingsgebied van de lidstaten van de Europese Unie en enkele andere Europese landen. |
| **EMREX-brug** { #begrip-emrex-brug } | Sectorale voorziening voor grensoverschrijdende uitwisseling van onderwijsgegevens. Dit is een voorbeeld van een sectorspecifieke aansluiting op [OOTS](#begrip-oots). |
| **Endpoint** { #begrip-endpoint } | Technisch adres waarop een [API](#begrip-api) of andere digitale dienst kan worden aangeroepen. |
| **EUDI-Wallet** { #begrip-eudi-wallet } | Europese digitale identiteitswallet waarin een burger identificatiegegevens en digitale [attestaties](#begrip-attestatie) kan ontvangen, bewaren en aan dienstverleners kan presenteren. |
| **Evidence Request** { #begrip-evidence-request } | Gestandaardiseerd [OOTS](#begrip-oots)-bericht waarmee een organisatie een bewijsstuk bij een [bronhouder](#begrip-bronhouder) in een andere lidstaat opvraagt. |
| **Evidence Response** { #begrip-evidence-response } | Gestandaardiseerd [OOTS](#begrip-oots)-antwoord waarmee het gevraagde bewijsstuk of informatie over de afhandeling van het verzoek wordt geleverd. |
| **Evidence type** { #begrip-evidence-type } | Binnen [OOTS](#begrip-oots) afgesproken categorie bewijsgegevens, zoals een bewijs van geboorte, inschrijving of behaald diploma. |
| **F1–F8** { #begrip-f1-f8 } | Nummering van de acht [generieke functies](#begrip-generieke-functie) die in het globaal ontwerp van [GBO](#begrip-gbo) worden onderscheiden. De functies beschrijven wat GBO functioneel moet ondersteunen. |
| **FDS** { #begrip-fds } | Federatief Datastelsel. Afsprakenstelsel waarmee publieke organisaties op basis van gemeenschappelijke technische, semantische, juridische en organisatorische afspraken gegevens kunnen vinden, delen en gebruiken. |
| **FSC** { #begrip-fsc } | *Federated Service Connectivity*. Standaard voor veilige en controleerbare gegevensuitwisseling tussen organisaties. FSC ondersteunt onder meer organisatie-authenticatie, afspraken over gegevensgebruik en logging. |
| **FSC Inway** { #begrip-fsc-inway } | [FSC](#begrip-fsc)-component aan de zijde van een gegevensaanbieder die binnenkomende gegevensverzoeken ontvangt en controleert. |
| **FSC Outway** { #begrip-fsc-outway } | [FSC](#begrip-fsc)-component aan de zijde van een [afnemer](#begrip-afnemer) waarmee gegevensverzoeken naar een aanbieder worden verzonden. |
| **FTV** { #begrip-ftv } | Federatieve Toegangsverlening. Autorisatieraamwerk voor federatieve gegevensuitwisseling, waarbij autorisatiebeslissingen door samenwerkende maar zelfstandig beheerde componenten worden uitgevoerd. |
| **GBO** { #begrip-gbo } | Gemeenschappelijke Bronontsluiting. Het geheel van afspraken, standaarden, voorzieningen en ondersteunende componenten waarmee overheidsbronnen op een uniforme manier voor verschillende toepassingen kunnen worden ontsloten. |
| **GBO-basis** { #begrip-gbo-basis } | Aanduiding in het globaal ontwerp voor de gemeenschappelijke voorzieningen voor bronontsluiting, [autorisatie](#begrip-autorisatie), [beleidsregels](#begrip-beleidsregel) en ondersteuning van [bronhouders](#begrip-bronhouder). |
| **GBO-component** { #begrip-gbo-component } | Voorziening die specifiek binnen [GBO](#begrip-gbo) wordt ontwikkeld of ingericht om één of meer [stelselfuncties](#begrip-stelselfunctie) te ondersteunen. |
| **GBO-vertaallaag** { #begrip-gbo-vertaallaag } | Ondersteunende voorziening voor [bronhouders](#begrip-bronhouder) die niet rechtstreeks de voorgeschreven [bronontsluiting-API](#begrip-bronontsluiting-api) kunnen aanbieden. De vertaallaag zet een bestaand koppelvlak of gegevensformaat om naar het binnen [GBO](#begrip-gbo) gebruikte koppelvlak of formaat. |
| **GDI** { #begrip-gdi } | Generieke Digitale Infrastructuur. Verzameling van overheidsbrede afspraken, standaarden en voorzieningen voor digitale dienstverlening en gegevensuitwisseling. |
| **Generieke bronontsluiting** { #begrip-generieke-bronontsluiting } | Functionele aanduiding voor het op een uniforme manier beschikbaar stellen van gegevens uit een bron voor meerdere toepassingen. Zie ook [**bronontsluiting-API**](#begrip-bronontsluiting-api). |
| **Generieke functie** { #begrip-generieke-functie } | Iets wat meerdere organisaties op een vergelijkbare manier moeten kunnen uitvoeren. Binnen [GBO](#begrip-gbo) beschrijft een generieke functie de benodigde functionaliteit, zonder direct een specifieke technische voorziening voor te schrijven. |
| **Gegevensset** { #begrip-gegevensset } | Afgebakende verzameling gegevens die voor een bepaalde dienst, toepassing of gegevensvraag beschikbaar kan worden gesteld. |
| **GraphQL** { #begrip-graphql } | Bevragingsprotocol waarmee een [afnemer](#begrip-afnemer) gericht kan aangeven welke gegevens nodig zijn. Binnen [GBO](#begrip-gbo) wordt GraphQL voorgesteld om hergebruik en [dataminimalisatie](#begrip-dataminimalisatie) bij de bronontsluiting te ondersteunen. |
| **Grondslag** { #begrip-grondslag } | Juridische reden waarom gegevens mogen worden verwerkt of verstrekt. Voorbeelden zijn een wettelijke taak, een wettelijke verplichting of, wanneer de wet dit toestaat, [toestemming](#begrip-toestemming) van de burger. |
| **Identity Matching** { #begrip-identity-matching } | Proces waarmee een vanuit een buitenlands of Europees identificatiemiddel verkregen identiteit wordt gekoppeld aan een in Nederland bekende persoon, bijvoorbeeld om het bijbehorende [BSN](#begrip-bsn) te bepalen. |
| **Informatiemodel** { #begrip-informatiemodel } | Formele beschrijving van informatieobjecten, kenmerken, relaties en regels binnen een bepaald domein. |
| **Interactiepatroon** { #begrip-interactiepatroon } | Op hoofdlijnen beschreven manier waarop actoren en voorzieningen samenwerken om gegevens uit te wisselen. [GBO](#begrip-gbo) onderscheidt patronen voor de [EUDI-Wallet](#begrip-eudi-wallet), [OOTS](#begrip-oots) en private dienstverleners. |
| **JSON** { #begrip-json } | Tekstgebaseerd formaat voor het gestructureerd uitwisselen van gegevens tussen systemen. |
| **LDV** { #begrip-ldv } | Logboek Dataverwerking. Standaard waarmee registraties van gegevensverwerkingen bij verschillende organisaties aan elkaar kunnen worden gekoppeld en aan de burger kunnen worden verantwoord. |
| **Mapping** { #begrip-mapping } | Vastgelegde relatie tussen begrippen, gegevenselementen of structuren uit verschillende modellen. Een mapping maakt geautomatiseerde omzetting of vergelijking mogelijk. |
| **mdoc** { #begrip-mdoc } | Op ISO 18013-5 gebaseerd formaat voor digitale documenten en [attestaties](#begrip-attestatie). Binnen de [EUDI-Wallet](#begrip-eudi-wallet) kan het onder meer worden gebruikt voor scenario's waarbij gegevens lokaal of op korte afstand worden gepresenteerd. |
| **MIM** { #begrip-mim } | Metamodel Informatiemodellering. Nederlandse standaard met regels voor het opstellen en uitwisselen van [informatiemodellen](#begrip-informatiemodel). |
| **mTLS** { #begrip-mtls } | *Mutual Transport Layer Security*. Beveiligde verbinding waarbij zowel de client als de server zich met een certificaat authenticeert. |
| **NL API Strategie** { #begrip-nl-api-strategie } | Overheidsbrede strategie en verzameling richtlijnen voor het ontwerpen, ontwikkelen, beveiligen en beheren van [API](#begrip-api)'s. |
| **NL-SBB** { #begrip-nl-sbb } | Nederlandse Standaard voor het Beschrijven van Begrippen. Standaard voor het eenduidig vastleggen van begrippen, definities, bronnen en onderlinge relaties. |
| **NORA** { #begrip-nora } | Nederlandse Overheid Referentie Architectuur. Overheidsbreed referentiekader met architectuurafspraken, principes en begrippen voor publieke dienstverlening. |
| **OAuth 2.0** { #begrip-oauth-2-0 } | Standaard waarmee een systeem namens een gebruiker of organisatie beperkte toegang tot een dienst kan verkrijgen met behulp van toegangstokens. |
| **OCI-bundle** { #begrip-oci-bundle } | Ondertekend en distribueerbaar pakket met machineleesbare [beleidsregels](#begrip-beleidsregel) of andere configuratie. Binnen [GBO](#begrip-gbo) kunnen dergelijke pakketten door een [PAP](#begrip-pap) aan [PDP](#begrip-pdp)'s worden aangeboden. |
| **ODRL** { #begrip-odrl } | *Open Digital Rights Language*. W3C-model voor het machineleesbaar beschrijven van rechten, verplichtingen, beperkingen en [beleidsregels](#begrip-beleidsregel) rond het gebruik van gegevens. |
| **OIN** { #begrip-oin } | Organisatie-identificatienummer waarmee Nederlandse overheidsorganisaties in digitaal verkeer kunnen worden geïdentificeerd. |
| **subOIN** { #begrip-suboin } | Identificatie van een onderdeel van een organisatie binnen de structuur van het Organisatie-identificatienummer. |
| **Once Only-principe** { #begrip-once-only-principe } | Uitgangspunt dat burgers en ondernemingen gegevens die al bij een overheid beschikbaar zijn niet opnieuw hoeven aan te leveren wanneer deze gegevens rechtmatig bij de oorspronkelijke bron kunnen worden opgehaald. |
| **OOTS** { #begrip-oots } | *Once-Only Technical System*. Europees technisch [stelsel](#begrip-stelsel) voor grensoverschrijdende uitwisseling van bewijsgegevens voor procedures die onder de [Single Digital Gateway](#begrip-sdg)-verordening vallen. |
| **OOTS-A** { #begrip-oots-a } | Onderdeel van de [Basisinrichting OOTS](#begrip-basisinrichting-oots) voor Nederlandse organisaties die bewijsgegevens uit andere Europese landen opvragen. De letter A verwijst naar de afnemende zijde. |
| **OOTS-adapter** { #begrip-oots-adapter } | [GBO-component](#begrip-gbo-component) die de aansluiting tussen de [generieke bronontsluiting](#begrip-generieke-bronontsluiting) en [OOTS](#begrip-oots) ondersteunt. De adapter verzorgt met name de [semantische mapping](#begrip-semantische-mapping) naar het door OOTS verwachte bewijsformaat. |
| **OOTS-EDM** { #begrip-oots-edm } | *[OOTS](#begrip-oots) Exchange Data Model*. Generiek berichtenmodel voor de uitwisseling van [Evidence Requests](#begrip-evidence-request) en [Evidence Responses](#begrip-evidence-response) binnen OOTS. Zie ook [**SDG-EDM**](#begrip-sdg-edm) |
| **OOTS-V** { #begrip-oots-v } | Onderdeel van de [Basisinrichting OOTS](#begrip-basisinrichting-oots) voor Nederlandse [bronhouders](#begrip-bronhouder) die bewijsgegevens aan organisaties in andere Europese landen verstrekken. De letter V verwijst naar de verstrekkende zijde. |
| **OpenID Connect** { #begrip-openid-connect } | Authenticatielaag boven op [OAuth 2.0](#begrip-oauth-2-0) waarmee een systeem informatie over de identiteit van een gebruiker kan ontvangen. |
| **OpenID4VCI** { #begrip-openid4vci } | *OpenID for Verifiable Credential Issuance*. Protocol voor het uitgeven en ophalen van verifieerbare [credentials](#begrip-credential), bijvoorbeeld voor opname in een [EUDI-Wallet](#begrip-eudi-wallet). |
| **OpenID4VP** { #begrip-openid4vp } | *OpenID for Verifiable Presentations*. Protocol waarmee een wallet één of meer [credentials](#begrip-credential) of geselecteerde [attributen](#begrip-attribuut) aan een dienstverlener kan presenteren. |
| **PAP** { #begrip-pap } | *Policy Administration Point*. Component waarin [beleidsregels](#begrip-beleidsregel) worden opgesteld, beheerd, goedgekeurd en beschikbaar gesteld aan de componenten die autorisatiebeslissingen nemen. |
| **Partijspecifiek pseudoniem** { #begrip-partijspecifiek-pseudoniem } | Pseudoniem dat alleen binnen de context van één specifieke afnemer bruikbaar is. Dezelfde persoon krijgt bij verschillende [afnemers](#begrip-afnemer) verschillende pseudoniemen. |
| **PBAC** { #begrip-pbac } | *Policy Based Access Control*. Autorisatiemodel waarbij toegangsbeslissingen worden genomen op basis van [beleidsregels](#begrip-beleidsregel) en kenmerken van het verzoek, de [afnemer](#begrip-afnemer), de gebruiker, het doel en de gegevens. |
| **PDP** { #begrip-pdp } | *Policy Decision Point*. Component die op basis van [beleidsregels](#begrip-beleidsregel) en beschikbare context bepaalt of een gegevensverzoek moet worden toegestaan. |
| **PEP** { #begrip-pep } | *Policy Enforcement Point*. Component die een gegevensverzoek onderschept, een autorisatiebeslissing opvraagt en de uitkomst daarvan afdwingt. |
| **PI** { #begrip-pi } | Polymorfe identiteit die binnen [BSNk PP](#begrip-bsnk-pp) wordt gebruikt als tussenrepresentatie van een identiteit. Binnen GBO is deze identiteit het [BSN](#begrip-bsn). |
| **PP** { #begrip-pp } | Polymorf pseudoniem dat binnen [BSNk PP](#begrip-bsnk-pp) wordt gebruikt als tussenrepresentatie voor een [pseudoniem](#begrip-partijspecifiek-pseudoniem). |
| **PID** { #begrip-pid } | *Person Identification Data*. Set identificerende persoonsgegevens die binnen het EUDI-Walletstelsel wordt gebruikt om de identiteit van een persoon aan te tonen. |
| **PIP** { #begrip-pip } | *Policy Information Point*. Bron waaruit een [PDP](#begrip-pdp) aanvullende informatie opvraagt die nodig is voor een autorisatiebeslissing, bijvoorbeeld een [toestemmingsregister](#begrip-toestemmingsregister), deelnemersregister of [dienstencatalogus](#begrip-dienstencatalogus). |
| **PKIoverheid-certificaat** { #begrip-pkioverheid-certificaat } | Digitaal certificaat binnen de Nederlandse PKIoverheid waarmee organisaties en systemen zich kunnen authenticeren en berichten kunnen beveiligen of ondertekenen. |
| **Policy** { #begrip-policy } | Machineleesbare [beleidsregel](#begrip-beleidsregel) die bepaalt onder welke voorwaarden een gegevensverzoek is toegestaan. |
| **Policy-bundle** { #begrip-policy-bundle } | Samenhangend, versioneerbaar en doorgaans ondertekend pakket van [beleidsregels](#begrip-beleidsregel) dat vanuit een [PAP](#begrip-pap) naar één of meer [PDP](#begrip-pdp)'s wordt gedistribueerd. |
| **PROV-O** { #begrip-prov-o } | W3C-ontologie voor het beschrijven van de herkomst van gegevens, waaronder de gegevensbronnen, bewerkingen en betrokken actoren. |
| **Pseudonimisering** { #begrip-pseudonimisering } | Verwerking waarbij direct identificerende gegevens worden vervangen door een pseudoniem. Aanvullende informatie is nodig om het pseudoniem weer aan de oorspronkelijke persoon te koppelen. |
| **PubEAA** { #begrip-pubeaa } | *Public Electronic Attestation of Attributes*. Elektronische [attestatie](#begrip-attestatie) van [attributen](#begrip-attribuut) die onder verantwoordelijkheid van een publieke organisatie wordt uitgegeven. |
| **PubEAA-provider** { #begrip-pubeaa-provider } | Technische voorziening waarmee een [bronhouder](#begrip-bronhouder) [PubEAA](#begrip-pubeaa)'s kan uitgeven aan een [EUDI-Wallet](#begrip-eudi-wallet). De bronhouder blijft verantwoordelijk voor de inhoud en uitgifte van de [attestatie](#begrip-attestatie). |
| **QEAA** { #begrip-qeaa } | *Qualified Electronic Attestation of Attributes*. Gekwalificeerde elektronische [attestatie](#begrip-attestatie) van [attributen](#begrip-attribuut) die door een [QTSP](#begrip-qtsp) wordt uitgegeven. |
| **QTSP** { #begrip-qtsp } | *Qualified Trust Service Provider*. Gekwalificeerde vertrouwensdienstverlener die onder [eIDAS](#begrip-eidas) vertrouwensdiensten aanbiedt en onder toezicht staat. Een QTSP kan [QEAA](#begrip-qeaa)'s uitgeven. |
| **RDF** { #begrip-rdf } | *Resource Description Framework*. W3C-standaard waarmee gegevens en hun onderlinge relaties machineleesbaar kunnen worden beschreven. |
| **RegRep** { #begrip-regrep } | Afkorting voor *Registry and Repository*. Standaard voor het registreren, opslaan en opzoeken van metadata en objecten, die binnen onderdelen van [OOTS](#begrip-oots) wordt toegepast. |
| **REST** { #begrip-rest } | Architectuurstijl voor [API](#begrip-api)'s waarbij gegevens en handelingen via gestandaardiseerde webverzoeken beschikbaar worden gesteld. |
| **Retrievedienst** { #begrip-retrievedienst } | [ASI](#begrip-asi)-functie waarmee een [QTSP](#begrip-qtsp) namens de [bronhouder](#begrip-bronhouder) [attributen](#begrip-attribuut) bij de authentieke bron ophaalt ten behoeve van de uitgifte van een [QEAA](#begrip-qeaa). |
| **S01–S11** { #begrip-s01-s11 } | Nummering van de [stelselfuncties](#begrip-stelselfunctie) die in het globaal ontwerp van [GBO](#begrip-gbo) zijn onderscheiden. De stelselfuncties beschrijven met welke afspraken, standaarden en voorzieningen de [generieke functies](#begrip-generieke-functie) worden ingevuld. |
| **Scope** { #begrip-scope } | Afbakening van de gegevens of handelingen waarop een [toestemming](#begrip-toestemming), toegangstoken of gegevensverzoek betrekking heeft. |
| **SDG** { #begrip-sdg } | *Single Digital Gateway*. Europees kader voor digitale toegang tot overheidsinformatie en procedures. [OOTS](#begrip-oots) ondersteunt de grensoverschrijdende uitwisseling van bewijsgegevens voor bepaalde SDG-procedures. |
| **SDG-EDM** { #begrip-sdg-edm } | *[Single Digital Gateway](#begrip-sdg) Evidence Data Model*. Semantisch model of schema waarmee bewijsgegevens voor een bepaald [evidence type](#begrip-evidence-type) op een geharmoniseerde manier worden beschreven. Zie ook [**OOTS-EDM**](#begrip-oots-edm) |
| **SD-JWT VC** { #begrip-sd-jwt-vc } | Formaat voor verifieerbare [credentials](#begrip-credential) dat gebruikmaakt van ondertekende [JSON](#begrip-json) Web Tokens en selectieve verstrekking ondersteunt. De burger kan daarmee alleen de voor een dienst benodigde [attributen](#begrip-attribuut) tonen. |
| **Semantic Repository** { #begrip-semantic-repository } | Europese [OOTS](#begrip-oots)-catalogus waarin onder meer [evidence types](#begrip-evidence-type), semantische afspraken en bijbehorende schema's of modellen worden geregistreerd. |
| **Semantiek** { #begrip-semantiek } | De betekenis van gegevens en de afspraken waarmee die betekenis eenduidig en machineleesbaar wordt vastgelegd. |
| **Semantische mapping** { #begrip-semantische-mapping } | Vastgelegde vertaling tussen begrippen en gegevenselementen uit verschillende [informatiemodellen](#begrip-informatiemodel). Binnen [GBO](#begrip-gbo) wordt dit onder meer gebruikt om brongegevens om te zetten naar [OOTS](#begrip-oots)-evidence types of EUDI-attestatieschema's. |
| **SHACL** { #begrip-shacl } | *Shapes Constraint Language*. W3C-standaard waarmee kan worden gecontroleerd of [RDF](#begrip-rdf)-gegevens voldoen aan vastgelegde structuur- en kwaliteitsregels. |
| **Signing-infrastructuur** { #begrip-signing-infrastructuur } | Geheel van certificaten, sleutels, procedures en technische voorzieningen waarmee [attestaties](#begrip-attestatie) digitaal worden ondertekend en hun authenticiteit kan worden gecontroleerd. |
| **SKOS** { #begrip-skos } | *Simple Knowledge Organization System*. W3C-standaard voor het machineleesbaar beschrijven en verbinden van begrippen, taxonomieën en andere kennisorganisatiesystemen. |
| **Stelsel** { #begrip-stelsel } | Samenhangend geheel van deelnemers, afspraken, standaarden, voorzieningen, rollen en governance waarmee organisaties gezamenlijk een functie uitvoeren. |
| **Stelselfunctie** { #begrip-stelselfunctie } | Concrete invulling van één of meer [generieke functies](#begrip-generieke-functie) door middel van afspraken, standaarden en/of voorzieningen. Een stelselfunctie beschrijft wat binnen het [stelsel](#begrip-stelsel) moet zijn georganiseerd. |
| **Toestemming** { #begrip-toestemming } | Vrije, specifieke, geïnformeerde en ondubbelzinnige wilsuiting van een burger waarmee verwerking van persoonsgegevens voor een bepaald doel wordt toegestaan. Binnen [GBO](#begrip-gbo) wordt toestemming alleen als [grondslag](#begrip-grondslag) gebruikt wanneer wet- en regelgeving dit mogelijk maakt. |
| **Toestemmingsportaal** { #begrip-toestemmingsportaal } | Burgerinterface voor het geven, inzien en intrekken van [toestemmingen](#begrip-toestemming). |
| **Toestemmingsregister** { #begrip-toestemmingsregister } | Centrale registratie waarin verleende en ingetrokken [toestemmingen](#begrip-toestemming) machineleesbaar worden vastgelegd en gecontroleerd. |
| **Toestemmingsvoorziening** { #begrip-toestemmingsvoorziening } | Overkoepelende [GBO](#begrip-gbo)-functie voor het verkrijgen, registreren, raadplegen en intrekken van [toestemming](#begrip-toestemming). De voorziening omvat onder meer het [toestemmingsportaal](#begrip-toestemmingsportaal), het [toestemmingsregister](#begrip-toestemmingsregister) en de benodigde interfaces. |
| **Trusted List** { #begrip-trusted-list } | Officiële lijst van erkende of gekwalificeerde vertrouwensdienstverleners en hun diensten. Een Trusted List kan worden gebruikt om vast te stellen of een [QTSP](#begrip-qtsp) of ondertekeningscertificaat wordt vertrouwd. |
| **TTL** { #begrip-ttl } | *Time To Live*. Periode gedurende welke een registratie, token, [toestemming](#begrip-toestemming) of ander technisch object geldig blijft. |
| **VC** { #begrip-vc } | *Verifiable [Credential](#begrip-credential)*. Digitaal bewijs waarvan de herkomst en integriteit cryptografisch kunnen worden gecontroleerd. |
| **Vertrouwensstelsel** { #begrip-vertrouwensstelsel } | Geheel van afspraken, toelatingsvoorwaarden, certificaten, registers en toezicht waarmee deelnemers elkaars identiteit en bevoegdheden kunnen vertrouwen. |
| **Verifydienst** { #begrip-verifydienst } | [ASI](#begrip-asi)-functie waarmee een [QTSP](#begrip-qtsp) controleert of door de QTSP aangeleverde [attributen](#begrip-attribuut) overeenkomen met de gegevens bij de authentieke bron. |
| **VI** { #begrip-vi } | Versleutelde identiteit die binnen [BSNk PP](#begrip-bsnk-pp) voor een specifieke partij wordt gegenereerd uit een [polymorfe identiteit](#begrip-pi). |
| **VP** { #begrip-vp } | Versleuteld pseudoniem dat binnen [BSNk PP](#begrip-bsnk-pp) voor een specifieke partij wordt gegenereerd uit een [polymorf pseudoniem](#begrip-pp). |
| **XML** { #begrip-xml } | *Extensible Markup Language*. Tekstgebaseerd formaat waarmee gestructureerde gegevens volgens een vooraf afgesproken schema kunnen worden vastgelegd en uitgewisseld. |
