# Begrippenlijst

In deze bijlage worden begrippen en afkortingen toegelicht die in het globaal ontwerp van Gemeenschappelijke Bronontsluiting worden gebruikt. De uitleg beschrijft wat het begrip binnen de context van GBO betekent. Het betreft daarmee niet altijd een volledige juridische of technische definitie.

| Begrip | Uitleg |
|---|---|
| **Afnemer** { #begrip-afnemer } | Organisatie of persoon die gegevens opvraagt bij een [bronhouder](#begrip-bronhouder). Dit kan bijvoorbeeld een overheidsorganisatie, een private dienstverlener, een burger met een [EUDI-Wallet](#begrip-eudi-wallet), een [QTSP](#begrip-qtsp) of een voorziening binnen een Europese gegevensuitwisseling zijn. |
| **API** { #begrip-api } | Application Programming Interface. Een gestandaardiseerd koppelvlak waarmee systemen geautomatiseerd gegevens of functionaliteit kunnen opvragen. |
| **ARF** { #begrip-arf } | Architecture and Reference Framework. Het Europese architectuur- en referentiekader met afspraken, protocollen en formaten voor de [EUDI-Wallet](#begrip-eudi-wallet). |
| **AS4** { #begrip-as4 } | Berichtenstandaard die binnen [e-Delivery](#begrip-e-delivery) en [OOTS](#begrip-oots) wordt gebruikt voor veilige grensoverschrijdende uitwisseling van berichten. De [Basisinrichting OOTS](#begrip-basisinrichting-oots) handelt het AS4-verkeer voor Nederlandse [bronhouders](#begrip-bronhouder) af. |
| **ASI** { #begrip-asi } | Authentic Source Interface. Gestandaardiseerd koppelvlak waarmee een [QTSP](#begrip-qtsp) gegevens bij een authentieke bron kan verifiëren of ophalen voor de uitgifte van een [QEAA](#begrip-qeaa). |
| **ASI-provider** { #begrip-asi-provider } | Technische voorziening die een [Authentic Source Interface](#begrip-asi) aanbiedt. In het globaal ontwerp wordt deze soms afgekort als ASI-P. |
| **Attestatie** { #begrip-attestatie } | Digitaal bewijs waarin één of meer [attributen](#begrip-attribuut) over een persoon of organisatie zijn opgenomen. Een attestatie kan in een [EUDI-Wallet](#begrip-eudi-wallet) worden opgeslagen en aan een dienstverlener worden getoond. |
| **Attestatieschema** { #begrip-attestatieschema } | Formele beschrijving van de [attributen](#begrip-attribuut), structuur, betekenis en technische representatie van een [attestatie](#begrip-attestatie). |
| **Attribuut** { #begrip-attribuut } | Afzonderlijk gegeven over een persoon, organisatie of object, zoals een geboortedatum, bevoegdheid, diploma of vestigingsadres. |
| **Audit trail** { #begrip-audit-trail } | Samenhangende en chronologische registratie waarmee achteraf kan worden vastgesteld wie welke gegevens heeft opgevraagd, op welke [grondslag](#begrip-grondslag) dit gebeurde en welke controles zijn uitgevoerd. |
| **Authenticatie** { #begrip-authenticatie } | Het vaststellen dat een persoon, organisatie of systeem daadwerkelijk de identiteit heeft die het beweert te hebben. |
| **AuthZEN** { #begrip-authzen } | Gestandaardiseerd koppelvlak van de OpenID Foundation voor de communicatie tussen een [PEP](#begrip-pep) en een [PDP](#begrip-pdp). AuthZEN maakt het mogelijk om onderdelen van de autorisatieketen onafhankelijk van elkaar te implementeren. GBO gebruikt hiervoor het Nederlandse overheidsprofiel *NLgov Profile for OpenID AuthZEN Authorization API*. |
| **Autorisatie** { #begrip-autorisatie } | Het bepalen of een geïdentificeerde en geauthenticeerde partij een bepaalde handeling mag uitvoeren of bepaalde gegevens mag opvragen. |
| **Basisinrichting OOTS** { #begrip-basisinrichting-oots } | Nederlandse voorziening voor aansluiting op het Europese [Once-Only Technical System](#begrip-oots). De voorziening handelt onder meer Europese berichten, herauthenticatie, inzage door de burger en verzending van bewijsgegevens af. |
| **Beleidsregel** { #begrip-beleidsregel } | Machineleesbare regel die bepaalt onder welke voorwaarden een gegevensverzoek is toegestaan. Een beleidsregel kan bijvoorbeeld betrekking hebben op de [afnemer](#begrip-afnemer), de [grondslag](#begrip-grondslag), het doel, de [gegevensset](#begrip-gegevensset) en de betrokken persoon. Ook aangeduid als [policy](#begrip-policy). |
| **Beleidsgedreven autorisatie** { #begrip-beleidsgedreven-autorisatie } | Vorm van [autorisatie](#begrip-autorisatie) waarbij toegangsbeslissingen worden genomen op basis van centraal of decentraal beheerde [beleidsregels](#begrip-beleidsregel). Zie ook [PBAC](#begrip-pbac). |
| **Begrippenkader** { #begrip-begrippenkader } | Gestructureerde verzameling begrippen met definities en onderlinge relaties. Het begrippenkader vormt een gemeenschappelijke basis voor de betekenis van gegevens binnen [GBO](#begrip-gbo). |
| **Bronhouder** { #begrip-bronhouder } | Organisatie die verantwoordelijk is voor een gegevensbron en voor het beschikbaar stellen van gegevens uit die bron. De bronhouder blijft verantwoordelijk voor de gegevens en de wijze waarop deze worden ontsloten, ook wanneer centrale GBO-voorzieningen worden gebruikt. |
| **Bronontsluiting-API** { #begrip-bronontsluiting-api } | Generiek koppelvlak waarmee een [bronhouder](#begrip-bronhouder) gegevens volgens de afspraken van de [gemeenschappelijke bronontsluiting](#begrip-gemeenschappelijke-bronontsluiting) beschikbaar stelt. Eén API kan verschillende gegevensverzoeken en [gegevensstromen](#begrip-gegevensstroom) verwerken. |
| **BSN** { #begrip-bsn } | Burgerservicenummer. Identificerend nummer voor personen die in de Nederlandse Basisregistratie Personen zijn opgenomen. Het BSN mag alleen worden verwerkt door partijen die daarvoor een wettelijke [grondslag](#begrip-grondslag) hebben. |
| **BSNk PP** { #begrip-bsnk-pp } | BSN-koppelregister voor polymorfe pseudoniemen. Voorziening waarmee identiteiten en pseudoniemen zodanig kunnen worden verwerkt dat een [afnemer](#begrip-afnemer) alleen een voor die afnemer bestemde identiteit of een [partijspecifiek pseudoniem](#begrip-partijspecifiek-pseudoniem) ontvangt. |
| **Canoniek gegevensmodel** { #begrip-canoniek-gegevensmodel } | Gestandaardiseerde beschrijving van de gegevens die een [bronhouder](#begrip-bronhouder) beschikbaar stelt. Het model vormt een stabiele representatie waarop [mappings](#begrip-mapping) naar toepassingsspecifieke formaten kunnen worden gebaseerd. |
| **Centrale voorziening** { #begrip-centrale-voorziening } | Voorziening die centraal beschikbaar wordt gesteld om een [kanaal](#begrip-kanaal) met de [gemeenschappelijke bronontsluiting](#begrip-gemeenschappelijke-bronontsluiting) te verbinden. GBO realiseert of past centrale voorzieningen aan zodat bronhouders deze niet ieder afzonderlijk hoeven te ontwikkelen. Of gebruik verplicht of optioneel is, hangt af van de betreffende [gegevensstroom](#begrip-gegevensstroom). |
| **Consent-id** { #begrip-consent-id } | Unieke identificatie van een geregistreerde [toestemming](#begrip-toestemming). Een private dienstverlener kan deze identificatie meegeven bij een gegevensverzoek, zodat de toestemming kan worden gecontroleerd. |
| **Credential** { #begrip-credential } | Digitaal bewijs met uitspraken over een persoon, organisatie of object. Binnen het [EUDI-Wallet](#begrip-eudi-wallet)-kanaal gaat het doorgaans om een verifieerbare credential. Zie ook [VC](#begrip-vc). |
| **Data Service Directory** { #begrip-data-service-directory } | Europese [OOTS](#begrip-oots)-catalogus waarin kan worden opgezocht welke gegevensdiensten en bewijsleveranciers een bepaald type bewijs kunnen leveren. Afgekort als [DSD](#begrip-dsd). |
| **Dataminimalisatie** { #begrip-dataminimalisatie } | Principe dat niet meer gegevens worden opgevraagd of verstrekt dan noodzakelijk is voor het doel van een dienst. GBO ondersteunt dit onder meer door selectieve gegevensuitvraag. |
| **DCAT-AP-NL** { #begrip-dcat-ap-nl } | Nederlands toepassingsprofiel van de Europese Data Catalog Vocabulary. Binnen GBO wordt DCAT-AP-NL gebruikt voor de gestandaardiseerde beschrijving en vindbaarheid van datasets en gegevensdiensten. |
| **Dienstencatalogus** { #begrip-dienstencatalogus } | Catalogus waarin wordt vastgelegd welke gegevens voor een bepaalde dienst of toepassing mogen worden opgevraagd. De catalogus kan onder meer beschrijven welke [afnemer](#begrip-afnemer) voor welk doel welke gegevens mag opvragen. |
| **Doelbinding** { #begrip-doelbinding } | Eis dat gegevens uitsluitend worden verwerkt voor een vooraf bepaald, uitdrukkelijk omschreven en gerechtvaardigd doel. |
| **DQV** { #begrip-dqv } | Data Quality Vocabulary. W3C-vocabulaire voor het beschrijven van de kwaliteit van datasets en kwaliteitsmetingen. |
| **DSD** { #begrip-dsd } | [Data Service Directory](#begrip-data-service-directory). Europese [OOTS](#begrip-oots)-catalogus waarin kan worden opgezocht welke gegevensdiensten en bewijsleveranciers een bepaald type bewijs kunnen leveren. |
| **DvTP** { #begrip-dvtp } | Gegevensstroom en [kanaal](#begrip-kanaal) waarin een burger overheidsgegevens laat verstrekken aan een private dienstverlener. Hiervoor zijn onder meer [toestemming](#begrip-toestemming), [doelbinding](#begrip-doelbinding) en [pseudonimisering](#begrip-pseudonimisering) relevant. |
| **EAA** { #begrip-eaa } | Electronic Attestation of Attributes. Elektronische [attestatie](#begrip-attestatie) waarin [attributen](#begrip-attribuut) over een persoon of organisatie zijn opgenomen. Een EAA kan bijvoorbeeld als [PubEAA](#begrip-pubeaa) of [QEAA](#begrip-qeaa) worden uitgegeven. |
| **eBMS** { #begrip-ebms } | ebXML Messaging Services. Berichtenstandaard waarop [AS4](#begrip-as4) is gebaseerd en die wordt gebruikt voor de betrouwbare uitwisseling van elektronische berichten. |
| **e-Delivery** { #begrip-e-delivery } | Europese bouwsteen voor veilige en betrouwbare elektronische gegevensuitwisseling. [OOTS](#begrip-oots) gebruikt een AS4-profiel van e-Delivery voor het berichtenverkeer tussen lidstaten. |
| **eID** { #begrip-eid } | Elektronisch identificatiemiddel waarmee een persoon digitaal zijn identiteit kan aantonen. |
| **eIDAS** { #begrip-eidas } | Europees juridisch kader voor elektronische identificatie en vertrouwensdiensten. De herziene verordening vormt onder meer de basis voor de [EUDI-Wallet](#begrip-eudi-wallet) en elektronische [attestaties](#begrip-attestatie) van attributen. |
| **eIDAS2** { #begrip-eidas2 } | Informele aanduiding voor de herziene Europese [eIDAS](#begrip-eidas)-verordening, die onder meer de juridische basis vormt voor de [EUDI-Wallet](#begrip-eudi-wallet). |
| **EMREX-brug** { #begrip-emrex-brug } | Sectorale voorziening voor grensoverschrijdende uitwisseling van onderwijsgegevens. Dit is een voorbeeld van een sectorspecifieke aansluiting op [OOTS](#begrip-oots). |
| **Endpoint** { #begrip-endpoint } | Technisch adres waarop een [API](#begrip-api) of andere digitale dienst kan worden aangeroepen. |
| **EUDI-Wallet** { #begrip-eudi-wallet } | Europese digitale identiteitswallet waarin een burger identificatiegegevens en digitale [attestaties](#begrip-attestatie) kan ontvangen, bewaren en aan dienstverleners kan presenteren. De EUDI-Wallet vormt één van de [kanalen](#begrip-kanaal) waarop GBO zich richt. |
| **Evidence Request** { #begrip-evidence-request } | Gestandaardiseerd [OOTS](#begrip-oots)-bericht waarmee een organisatie bewijsgegevens bij een bron in een andere lidstaat opvraagt. |
| **Evidence Response** { #begrip-evidence-response } | Gestandaardiseerd [OOTS](#begrip-oots)-antwoord waarmee de gevraagde bewijsgegevens of informatie over de afhandeling van het verzoek worden geleverd. |
| **Evidence type** { #begrip-evidence-type } | Binnen [OOTS](#begrip-oots) afgesproken categorie bewijsgegevens, zoals bewijs van geboorte, inschrijving of een behaald diploma. |
| **FDS** { #begrip-fds } | Federatief Datastelsel. Afsprakenstelsel waarmee publieke organisaties op basis van gemeenschappelijke technische, semantische, juridische en organisatorische afspraken gegevens kunnen vinden, delen en gebruiken. GBO gebruikt en vult waar nodig afspraken en standaarden van het FDS aan. |
| **FSC** { #begrip-fsc } | Federated Service Connectivity. Standaard voor veilige en controleerbare gegevensuitwisseling tussen organisaties. FSC ondersteunt onder meer organisatie-authenticatie, afspraken over gegevensgebruik en logging. |
| **FSC Inway** { #begrip-fsc-inway } | [FSC](#begrip-fsc)-component aan de zijde van een gegevensaanbieder die binnenkomende gegevensverzoeken ontvangt en controleert. |
| **FSC Outway** { #begrip-fsc-outway } | [FSC](#begrip-fsc)-component aan de zijde van een [afnemer](#begrip-afnemer) waarmee gegevensverzoeken naar een aanbieder worden verzonden. |
| **FTV** { #begrip-ftv } | Federatieve Toegangsverlening. Autorisatieraamwerk voor federatieve gegevensuitwisseling, waarbij autorisatiebeslissingen door samenwerkende maar zelfstandig beheerde componenten worden uitgevoerd. |
| **GBO** { #begrip-gbo } | Gemeenschappelijke Bronontsluiting. Het geheel van afspraken, standaarden, voorzieningen en ondersteunende componenten waarmee overheidsbronnen op een uniforme en herbruikbare manier voor verschillende gegevensstromen en toepassingen kunnen worden ontsloten. |
| **GBO-basis** { #begrip-gbo-basis } | Aanduiding in het globaal ontwerp voor het generieke, decentrale deel van GBO bij de bronhouder. Hieronder vallen onder meer de generieke bronontsluiting, configureerbare autorisatie, beleidsregels en ondersteuning voor bronhouders. |
| **GBO-configuratie** { #begrip-gbo-configuratie } | Bronspecifieke configuratie waarmee een [bronhouder](#begrip-bronhouder) vastlegt hoe centrale GBO-voorzieningen voor zijn bron moeten functioneren. Deze configuratie bevat onder meer informatie over beschikbare diensten en [semantische mappings](#begrip-semantische-mapping) en wordt beheerd met het decentrale configuratiecomponent. |
| **GBO-vertaallaag** { #begrip-gbo-vertaallaag } | Optionele [referentiecomponent](#begrip-referentiecomponent) voor bronhouders die niet rechtstreeks het binnen GBO afgesproken koppelvlak of gegevensformaat kunnen aanbieden. De vertaallaag zet een bestaand koppelvlak of formaat om naar het door GBO gebruikte koppelvlak of formaat. |
| **Gemeenschappelijke bronontsluiting** { #begrip-gemeenschappelijke-bronontsluiting } | Het volgens gemeenschappelijke afspraken, standaarden en koppelvlakken beschikbaar stellen van gegevens door een [bronhouder](#begrip-bronhouder), zodat één ontsluiting voor verschillende typen afnemers, [gegevensstromen](#begrip-gegevensstroom) en [kanalen](#begrip-kanaal) kan worden hergebruikt. De bronhouder richt deze ontsluiting zelf in of laat dit door een leverancier doen. |
| **Generieke bronontsluiting** { #begrip-generieke-bronontsluiting } | Technische en functionele aanduiding voor het generieke deel van de bronontsluiting bij een [bronhouder](#begrip-bronhouder). Deze ondersteunt het hergebruik van dezelfde ontsluiting voor verschillende gegevensverzoeken en vormt de basis van de [gemeenschappelijke bronontsluiting](#begrip-gemeenschappelijke-bronontsluiting). |
| **Generieke functie** { #begrip-generieke-functie } | Iets wat meerdere organisaties op een vergelijkbare manier moeten kunnen uitvoeren. Binnen GBO beschrijft een generieke functie de benodigde functionaliteit, zonder direct een specifieke technische voorziening voor te schrijven. |
| **Gegevensset** { #begrip-gegevensset } | Afgebakende verzameling gegevens die voor een bepaalde dienst, toepassing of gegevensvraag beschikbaar kan worden gesteld. |
| **Gegevensstroom** { #begrip-gegevensstroom } | Concrete uitwisseling of route van gegevens tussen een [bronhouder](#begrip-bronhouder) en een [afnemer](#begrip-afnemer) voor een bepaald doel. Voor verschillende gegevensstromen kunnen verschillende eisen gelden aan onder meer gegevenssets, autorisatie, protocollen, grondslag en te gebruiken voorzieningen. |
| **GraphQL** { #begrip-graphql } | Bevragingsprotocol waarmee een [afnemer](#begrip-afnemer) gericht kan aangeven welke gegevens nodig zijn. Binnen GBO wordt GraphQL gebruikt als mechanisme voor selectieve bevraging en [dataminimalisatie](#begrip-dataminimalisatie) bij de bronontsluiting. |
| **Grondslag** { #begrip-grondslag } | Juridische reden waarom gegevens mogen worden verwerkt of verstrekt. Voorbeelden zijn een wettelijke taak, een wettelijke verplichting of, wanneer wet- en regelgeving dit toestaat, [toestemming](#begrip-toestemming) van de burger. |
| **Identity Matching** { #begrip-identity-matching } | Proces waarmee een vanuit een buitenlands of Europees identificatiemiddel verkregen identiteit wordt gekoppeld aan een in Nederland bekende persoon, bijvoorbeeld om het bijbehorende [BSN](#begrip-bsn) te bepalen. |
| **Informatiemodel** { #begrip-informatiemodel } | Formele beschrijving van informatieobjecten, kenmerken, relaties en regels binnen een bepaald domein. |
| **Interactiepatroon** { #begrip-interactiepatroon } | Op hoofdlijnen beschreven manier waarop actoren en voorzieningen samenwerken om gegevens uit te wisselen. Het globaal ontwerp beschrijft interactiepatronen voor de [EUDI-Wallet](#begrip-eudi-wallet), [OOTS](#begrip-oots) en private dienstverleners. |
| **JSON** { #begrip-json } | Tekstgebaseerd formaat voor het gestructureerd uitwisselen van gegevens tussen systemen. |
| **Kanaal** { #begrip-kanaal } | Route of toepassingscontext waarlangs gegevens uit de [gemeenschappelijke bronontsluiting](#begrip-gemeenschappelijke-bronontsluiting) voor een bepaalde categorie toepassingen of afnemers beschikbaar worden gesteld. GBO richt zich op de kanalen EUDI-Wallet, OOTS en private dienstverleners (DvTP). De gemeenschappelijke bronontsluiting kan in de toekomst ook door andere kanalen worden hergebruikt. |
| **LDV** { #begrip-ldv } | Logboek Dataverwerking. Standaard waarmee registraties van gegevensverwerkingen bij verschillende organisaties aan elkaar kunnen worden gekoppeld en aan de burger kunnen worden verantwoord. |
| **Mapping** { #begrip-mapping } | Vastgelegde relatie tussen begrippen, gegevenselementen of structuren uit verschillende modellen. Een mapping maakt geautomatiseerde omzetting of vergelijking mogelijk. |
| **mdoc** { #begrip-mdoc } | Op ISO 18013-5 gebaseerd formaat voor digitale documenten en [attestaties](#begrip-attestatie). Binnen de [EUDI-Wallet](#begrip-eudi-wallet) kan het onder meer worden gebruikt voor scenario's waarbij gegevens lokaal of op korte afstand worden gepresenteerd. |
| **MIM** { #begrip-mim } | Metamodel Informatiemodellering. Nederlandse standaard met regels voor het opstellen en uitwisselen van [informatiemodellen](#begrip-informatiemodel). |
| **mTLS** { #begrip-mtls } | Mutual Transport Layer Security. Beveiligde verbinding waarbij zowel de client als de server zich met een certificaat authenticeert. |
| **NL API Strategie** { #begrip-nl-api-strategie } | Overheidsbrede strategie en verzameling richtlijnen voor het ontwerpen, ontwikkelen, beveiligen en beheren van [API's](#begrip-api). |
| **NL-SBB** { #begrip-nl-sbb } | Nederlandse Standaard voor het Beschrijven van Begrippen. Standaard voor het eenduidig vastleggen van begrippen, definities, bronnen en onderlinge relaties. |
| **NORA** { #begrip-nora } | Nederlandse Overheid Referentie Architectuur. Overheidsbreed referentiekader met architectuurafspraken, principes en begrippen voor publieke dienstverlening. |
| **OAuth 2.0** { #begrip-oauth-2 } | Standaard waarmee een systeem namens een gebruiker of organisatie beperkte toegang tot een dienst kan verkrijgen met behulp van toegangstokens. |
| **ODRL** { #begrip-odrl } | Open Digital Rights Language. W3C-model voor het machineleesbaar beschrijven van rechten, verplichtingen, beperkingen en [beleidsregels](#begrip-beleidsregel) rond het gebruik van gegevens. |
| **OIN** { #begrip-oin } | Organisatie-identificatienummer waarmee Nederlandse overheidsorganisaties in digitaal verkeer kunnen worden geïdentificeerd. |
| **OOTS** { #begrip-oots } | Once-Only Technical System. Europees technisch [stelsel](#begrip-stelsel) voor grensoverschrijdende uitwisseling van bewijsgegevens voor procedures die onder de Single Digital Gateway-verordening vallen. OOTS vormt één van de [kanalen](#begrip-kanaal) waarop GBO zich richt. |
| **OOTS-adapter** { #begrip-oots-adapter } | [Centrale voorziening](#begrip-centrale-voorziening) die de [gemeenschappelijke bronontsluiting](#begrip-gemeenschappelijke-bronontsluiting) aansluit op de [Basisinrichting OOTS](#begrip-basisinrichting-oots). De adapter ondersteunt onder meer protocolvertaling en kan, indien geconfigureerd, semantische vertaling naar het door OOTS verwachte gegevensmodel uitvoeren. |
| **OOTS-EDM** { #begrip-oots-edm } | OOTS Exchange Data Model. Generiek berichtenmodel voor de uitwisseling van [Evidence Requests](#begrip-evidence-request) en [Evidence Responses](#begrip-evidence-response) binnen OOTS. |
| **OOTS-V** { #begrip-oots-v } | Onderdeel van de [Basisinrichting OOTS](#begrip-basisinrichting-oots) voor Nederlandse [bronhouders](#begrip-bronhouder) die bewijsgegevens aan organisaties in andere Europese landen verstrekken. De letter V verwijst naar de verstrekkende zijde. |
| **OpenID Connect** { #begrip-openid-connect } | Authenticatielaag boven op [OAuth 2.0](#begrip-oauth-2) waarmee een systeem informatie over de identiteit van een gebruiker kan ontvangen. Voor de Nederlandse overheid wordt hiervoor een specifiek overheidsprofiel gebruikt. |
| **OpenID4VCI** { #begrip-openid4vci } | OpenID for Verifiable Credential Issuance. Protocol voor het uitgeven en ophalen van verifieerbare [credentials](#begrip-credential), bijvoorbeeld voor opname in een [EUDI-Wallet](#begrip-eudi-wallet). |
| **OpenID4VP** { #begrip-openid4vp } | OpenID for Verifiable Presentations. Protocol waarmee een wallet één of meer [credentials](#begrip-credential) of geselecteerde [attributen](#begrip-attribuut) aan een dienstverlener kan presenteren. |
| **PAP** { #begrip-pap } | Policy Administration Point. Component waarin [beleidsregels](#begrip-beleidsregel) worden opgesteld, beheerd, goedgekeurd en beschikbaar gesteld aan de componenten die autorisatiebeslissingen nemen. |
| **Partijspecifiek pseudoniem** { #begrip-partijspecifiek-pseudoniem } | Pseudoniem dat alleen binnen de context van één specifieke afnemer bruikbaar is. Dezelfde persoon krijgt bij verschillende [afnemers](#begrip-afnemer) verschillende pseudoniemen. |
| **PBAC** { #begrip-pbac } | Policy Based Access Control. Autorisatiemodel waarbij toegangsbeslissingen worden genomen op basis van [beleidsregels](#begrip-beleidsregel) en kenmerken van onder meer het verzoek, de afnemer, de gebruiker, het doel en de gegevens. |
| **PDP** { #begrip-pdp } | Policy Decision Point. Component die op basis van [beleidsregels](#begrip-beleidsregel) en beschikbare context bepaalt of een gegevensverzoek moet worden toegestaan. |
| **PEP** { #begrip-pep } | Policy Enforcement Point. Component die een gegevensverzoek onderschept, een autorisatiebeslissing opvraagt en de uitkomst daarvan afdwingt. |
| **PI** { #begrip-pi } | Polymorfe identiteit die binnen [BSNk PP](#begrip-bsnk-pp) wordt gebruikt als tussenrepresentatie van een identiteit. Binnen GBO is deze identiteit afgeleid van het [BSN](#begrip-bsn). |
| **PID** { #begrip-pid } | Person Identification Data. Set identificerende persoonsgegevens die binnen het EUDI-Walletstelsel wordt gebruikt om de identiteit van een persoon aan te tonen. |
| **PIP** { #begrip-pip } | Policy Information Point. Bron waaruit een [PDP](#begrip-pdp) aanvullende informatie opvraagt die nodig is voor een autorisatiebeslissing, bijvoorbeeld een [toestemmingsregister](#begrip-toestemmingsregister), deelnemersregister of [dienstencatalogus](#begrip-dienstencatalogus). |
| **PKIoverheid-certificaat** { #begrip-pkioverheid-certificaat } | Digitaal certificaat binnen PKIoverheid waarmee organisaties en systemen zich kunnen authenticeren en berichten kunnen beveiligen of ondertekenen. |
| **Policy** { #begrip-policy } | Machineleesbare [beleidsregel](#begrip-beleidsregel) die bepaalt onder welke voorwaarden een gegevensverzoek is toegestaan. |
| **PP** { #begrip-pp } | Polymorf pseudoniem dat binnen [BSNk PP](#begrip-bsnk-pp) wordt gebruikt als tussenrepresentatie voor een pseudoniem. |
| **PROV-O** { #begrip-prov-o } | W3C-ontologie voor het beschrijven van de herkomst van gegevens, waaronder gegevensbronnen, bewerkingen en betrokken actoren. |
| **Pseudonimisering** { #begrip-pseudonimisering } | Verwerking waarbij direct identificerende gegevens worden vervangen door een pseudoniem. Aanvullende informatie is nodig om het pseudoniem weer aan de oorspronkelijke persoon te koppelen. |
| **Pseudonimiseervoorziening** { #begrip-pseudonimiseervoorziening } | [Centrale voorziening](#begrip-centrale-voorziening) binnen het DvTP-kanaal die voorkomt dat het [BSN](#begrip-bsn) bij een private dienstverlener terechtkomt die geen wettelijke grondslag heeft om het BSN te verwerken. Hiervoor wordt gebruikgemaakt van partijspecifieke pseudoniemen. |
| **PubEAA** { #begrip-pubeaa } | Public Electronic Attestation of Attributes. Elektronische [attestatie](#begrip-attestatie) van attributen die onder verantwoordelijkheid van een publieke organisatie wordt uitgegeven. |
| **PubEAA-provider** { #begrip-pubeaa-provider } | [Centrale voorziening](#begrip-centrale-voorziening) waarmee een [bronhouder](#begrip-bronhouder) PubEAA's kan uitgeven aan een [EUDI-Wallet](#begrip-eudi-wallet). De bronhouder blijft verantwoordelijk voor de inhoud en uitgifte van de attestatie. |
| **QEAA** { #begrip-qeaa } | Qualified Electronic Attestation of Attributes. Gekwalificeerde elektronische [attestatie](#begrip-attestatie) van attributen die door een [QTSP](#begrip-qtsp) wordt uitgegeven. |
| **QTSP** { #begrip-qtsp } | Qualified Trust Service Provider. Gekwalificeerde vertrouwensdienstverlener die onder [eIDAS](#begrip-eidas) vertrouwensdiensten aanbiedt en onder toezicht staat. Een QTSP kan [QEAA's](#begrip-qeaa) uitgeven. |
| **RDF** { #begrip-rdf } | Resource Description Framework. W3C-standaard waarmee gegevens en hun onderlinge relaties machineleesbaar kunnen worden beschreven. |
| **Referentiecomponent** { #begrip-referentiecomponent } | Door of namens GBO beschikbaar gestelde technische implementatie waarmee een deel van de GBO-afspraken kan worden gerealiseerd. Het gebruik van een referentiecomponent is optioneel: een bronhouder mag ook een functioneel gelijkwaardig alternatief gebruiken dat aan dezelfde afspraken en standaarden voldoet. |
| **Referentie-implementatie** { #begrip-referentie-implementatie } | Werkende voorbeeldimplementatie van de [gemeenschappelijke bronontsluiting](#begrip-gemeenschappelijke-bronontsluiting). Bronhouders kunnen deze gebruiken, maar mogen ook een eigen oplossing toepassen die aan dezelfde afspraken en standaarden voldoet. |
| **RegRep** { #begrip-regrep } | Afkorting voor Registry and Repository. Standaard voor het registreren, opslaan en opzoeken van metadata en objecten, die binnen onderdelen van [OOTS](#begrip-oots) wordt toegepast. |
| **REST** { #begrip-rest } | Architectuurstijl voor [API's](#begrip-api) waarbij gegevens en handelingen via gestandaardiseerde webverzoeken beschikbaar worden gesteld. |
| **Retrievedienst** { #begrip-retrievedienst } | [ASI](#begrip-asi)-functie waarmee een [QTSP](#begrip-qtsp) gegevens bij de authentieke bron ophaalt ten behoeve van de uitgifte van een [QEAA](#begrip-qeaa). |
| **Scope** { #begrip-scope } | Afbakening van de gegevens of handelingen waarop een [toestemming](#begrip-toestemming), toegangstoken of gegevensverzoek betrekking heeft. |
| **SDG** { #begrip-sdg } | Single Digital Gateway. Europees kader voor digitale toegang tot overheidsinformatie en procedures. [OOTS](#begrip-oots) ondersteunt de grensoverschrijdende uitwisseling van bewijsgegevens voor bepaalde SDG-procedures. |
| **SDG-EDM** { #begrip-sdg-edm } | Single Digital Gateway Evidence Data Model. Semantisch model of schema waarmee bewijsgegevens voor een bepaald [evidence type](#begrip-evidence-type) op een geharmoniseerde manier worden beschreven. |
| **SD-JWT VC** { #begrip-sd-jwt-vc } | Formaat voor verifieerbare [credentials](#begrip-credential) dat gebruikmaakt van ondertekende JSON Web Tokens en selectieve verstrekking ondersteunt. De burger kan daarmee alleen de voor een dienst benodigde attributen tonen. |
| **Semantic Repository** { #begrip-semantic-repository } | Europese [OOTS](#begrip-oots)-catalogus waarin onder meer evidence types, semantische afspraken en bijbehorende schema's of modellen worden geregistreerd. |
| **Semantiek** { #begrip-semantiek } | De betekenis van gegevens en de afspraken waarmee die betekenis eenduidig en machineleesbaar wordt vastgelegd. |
| **Semantische mapping** { #begrip-semantische-mapping } | Vastgelegde vertaling tussen begrippen en gegevenselementen uit verschillende [informatiemodellen](#begrip-informatiemodel). Binnen GBO wordt dit onder meer gebruikt om brongegevens om te zetten naar een voor een specifiek kanaal vereist model of attestatieschema. |
| **SHACL** { #begrip-shacl } | Shapes Constraint Language. W3C-standaard waarmee kan worden gecontroleerd of [RDF](#begrip-rdf)-gegevens voldoen aan vastgelegde structuur- en kwaliteitsregels. |
| **Signing-infrastructuur** { #begrip-signing-infrastructuur } | Geheel van certificaten, sleutels, procedures en technische voorzieningen waarmee [attestaties](#begrip-attestatie) digitaal worden ondertekend en hun authenticiteit kan worden gecontroleerd. |
| **SKOS** { #begrip-skos } | Simple Knowledge Organization System. W3C-standaard voor het machineleesbaar beschrijven en verbinden van begrippen, taxonomieën en andere kennisorganisatiesystemen. |
| **Stelsel** { #begrip-stelsel } | Samenhangend geheel van deelnemers, afspraken, standaarden, voorzieningen, rollen en governance waarmee organisaties gezamenlijk een functie uitvoeren. |
| **Stelselfunctie** { #begrip-stelselfunctie } | Concrete invulling van één of meer [generieke functies](#begrip-generieke-functie) door middel van afspraken, standaarden en/of voorzieningen. Een stelselfunctie beschrijft wat binnen het [stelsel](#begrip-stelsel) moet zijn georganiseerd. |
| **subOIN** { #begrip-suboin } | Identificatie van een onderdeel van een organisatie binnen de structuur van het [Organisatie-identificatienummer](#begrip-oin). |
| **Toestemming** { #begrip-toestemming } | Vrije, specifieke, geïnformeerde en ondubbelzinnige wilsuiting van een burger waarmee verwerking van persoonsgegevens voor een bepaald doel wordt toegestaan. Binnen GBO wordt toestemming alleen als [grondslag](#begrip-grondslag) gebruikt wanneer wet- en regelgeving dit mogelijk maakt. |
| **Toestemmingsportaal** { #begrip-toestemmingsportaal } | Burgerinterface voor het geven, inzien en intrekken van [toestemmingen](#begrip-toestemming). |
| **Toestemmingsregister** { #begrip-toestemmingsregister } | Centrale registratie waarin verleende en ingetrokken [toestemmingen](#begrip-toestemming) machineleesbaar worden vastgelegd en gecontroleerd. |
| **Toestemmingsvoorziening** { #begrip-toestemmingsvoorziening } | [Centrale voorziening](#begrip-centrale-voorziening) voor het verkrijgen, registreren, raadplegen en intrekken van [toestemming](#begrip-toestemming) binnen het DvTP-kanaal. De voorziening omvat onder meer het [toestemmingsportaal](#begrip-toestemmingsportaal), het [toestemmingsregister](#begrip-toestemmingsregister) en de benodigde interfaces. |
| **Trusted List** { #begrip-trusted-list } | Officiële lijst van erkende of gekwalificeerde vertrouwensdienstverleners en hun diensten. Een Trusted List kan worden gebruikt om vast te stellen of een [QTSP](#begrip-qtsp) of ondertekeningscertificaat wordt vertrouwd. |
| **TTL** { #begrip-ttl } | Time To Live. Periode gedurende welke een registratie, token, [toestemming](#begrip-toestemming) of ander technisch object geldig blijft. |
| **VC** { #begrip-vc } | Verifiable Credential. Digitaal bewijs waarvan de herkomst en integriteit cryptografisch kunnen worden gecontroleerd. Zie ook [credential](#begrip-credential). |
| **Vertrouwensstelsel** { #begrip-vertrouwensstelsel } | Geheel van afspraken, toelatingsvoorwaarden, certificaten, registers en toezicht waarmee deelnemers elkaars identiteit en bevoegdheden kunnen vertrouwen. |
| **Verifydienst** { #begrip-verifydienst } | [ASI](#begrip-asi)-functie waarmee een [QTSP](#begrip-qtsp) controleert of door de QTSP aangeleverde attributen overeenkomen met de gegevens bij de authentieke bron. |
| **VI** { #begrip-vi } | Versleutelde identiteit die binnen [BSNk PP](#begrip-bsnk-pp) voor een specifieke partij wordt gegenereerd uit een polymorfe identiteit. |
| **VP** { #begrip-vp } | Versleuteld pseudoniem dat binnen [BSNk PP](#begrip-bsnk-pp) voor een specifieke partij wordt gegenereerd uit een polymorf pseudoniem. |
| **XML** { #begrip-xml } | Extensible Markup Language. Tekstgebaseerd formaat waarmee gestructureerde gegevens volgens een vooraf afgesproken schema kunnen worden vastgelegd en uitgewisseld. |
